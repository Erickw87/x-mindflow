# x-mindflow - 企业级智能发布系统

## 📌 项目简介

**x-mindflow** 是一个企业内部使用的智能发布系统，支持多版本并行部署、统一多环境管理和自动化故障回滚。

### 核心价值主张

通过**逻辑-物理分离**的架构设计，实现面向状态的渐进式发布，以**负载均衡器(LB)为核心**的流量控制机制，提供统一的发布体验，无论是 Kubernetes 还是物理机环境。

## ✨ 核心特性

- 🚀 **多版本并行发布与渐进式灰度** - 支持金丝雀发布,同一服务可同时运行 2-3 个版本(如 v1.1 在发布过程中即可开始 v1.2 发布)
- 🌐 **统一多环境支持** - 单一逻辑支持 Kubernetes 和裸金属环境
- 🔄 **自动故障回滚** - 智能检测问题并自动回滚（计划中）
- 📊 **拓扑可视化** - 横向树状布局展示服务版本和流量分布
- 🏷️ **流量标记** - 基于 HTTP Header 的跨服务路由

## 🏗️ 架构设计

### 逻辑-物理分离架构

```
┌──────────────────────────────┐
│      发布系统逻辑层（核心抽象层）   │ ← 统一逻辑模型、发布控制、状态机、策略引擎
├──────────────────────────────┤
│   环境适配层（Environment Adapter）│ ← 负责调用 K8s / 物理环境 的接口或代理
├──────────────────────────────┤
│   执行环境（Execution Environment）│ ← 实际运行的物理机或 K8s 集群
└──────────────────────────────┘
```

### 核心设计原则

- **逻辑与物理分离** - 统一抽象层 + 环境适配器
- **面向状态的发布** - 声明式配置驱动
- **以 LB 为核心的流量控制** - 拓扑即配置
- **最小化功能集** - 避免重复造轮，复用现有组件

### LB 驱动的流量控制

系统以负载均衡器为核心实现流量管理：

- 通过 LB 配置定义服务拓扑关系
- 流量标签在 HTTP Header 中传递
- LB 配置自动生成可视化拓扑图
- 图形化界面直接编辑 LB 配置

## 🔧 技术栈

### 后端
- **语言**: Go 1.24
- **Web 框架**: Gin
- **ORM**: GORM
- **缓存**: freecache (内存缓存)
- **日志**: uber-go/zap
- **数据库**: PostgreSQL 18.0

### 前端
- **运行时**: Node.js 20
- **框架**: Vue 3 + TypeScript
- **状态管理**: Pinia
- **HTTP 客户端**: Axios
- **样式方案**: Tailwind CSS
- **图可视化**: AntV G6

### API 协议
- HTTP + JSON
- 遵循 RESTful API 规范

### 部署方式
- **开发环境**: Docker Compose
- **生产环境**: Kubernetes (K8s)

## 🚀 快速开始

### 前置依赖
- Go 1.24+
- Node.js 20+
- PostgreSQL 18.0+
- Docker & Docker Compose
- Make

### 一键启动开发环境

```bash
# 初始化项目（安装依赖、数据库迁移等）
make init

# 启动完整开发环境（前端 + 后端 + 数据库）
make dev

# 仅启动后端
make dev-backend

# 仅启动前端
make dev-frontend
```

### 构建项目

```bash
# 构建所有组件
make build

# 构建后端
make build-backend

# 构建前端
make build-frontend
```

## 🎯 核心功能模块

### 1. 统一发布抽象层
- 资源对象模型（Application、Deployment、Service、Instance）
- 发布控制器（状态机、策略支持）
- 状态聚合器（多环境状态汇总）

### 2. 环境适配层
- **Kubernetes 适配器**: 通过 K8s API 管理资源
- **BareMetal 适配器**: 轻量 Agent + Registry + Edge Proxy

### 3. 流量控制与拓扑管理
- LB 配置即拓扑
- 流量标签传递机制
- 拓扑图自动生成与图形化编辑

### 4. 多版本并行与灰度发布
- 实例维度控制（逐步创建/销毁）
- 流量维度控制（权重调整）
- 不兼容更新支持（独立拓扑树）

### 5. 拓扑可视化
- 横向树形布局
- 饼图显示版本分布
- 流量百分比实时计算
- 拖拽式交互编辑

## 🔒 安全规范

1. **敏感信息**: 使用环境变量，禁止硬编码
2. **密码存储**: 必须加密（bcrypt 或 argon2）
3. **SQL 注入防护**: 使用 GORM 参数化查询
4. **XSS 防护**: 前端输入验证 + 后端转义
5. **CSRF 防护**: 使用 CSRF Token
6. **API 认证**: JWT Token + Refresh Token 机制
