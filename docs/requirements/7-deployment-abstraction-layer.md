# 统一发布抽象层

## 产品概述

统一发布抽象层是 x-mindflow 智能发布系统的核心组件,提供环境无关的应用发布管理能力。通过声明式配置和自动化流程,简化应用部署、版本管理和故障恢复。

## 核心功能

### 1. 渐进式发布

支持灵活的渐进式发布策略,用户可以自定义发布阶梯,控制新版本的推广节奏:

- 按百分比逐步发布新版本
- 可配置的发布暂停时间
- 支持发布过程中的健康检查

### 2. 自动回滚

系统自动监控应用运行状况,在检测到异常时自动回滚到稳定版本:

- **启动失败检测**: 应用启动连续失败时触发回滚
- **性能监控**: CPU、内存等资源使用超过阈值时触发回滚
- **健康检查**: 健康检查失败率超标时触发回滚
- **通知机制**: 通过企业微信及时通知运维人员

### 3. 版本管理

完善的版本历史管理,支持快速回退到任意历史版本:

- 自动保留最近 30 个版本历史
- 支持查看版本配置快照
- 一键回滚到指定版本
- 版本状态跟踪(运行中/已停止/不稳定)

### 4. 环境适配

统一的抽象层设计,屏蔽底层环境差异:

- 支持 Kubernetes 集群环境
- 支持裸金属(BareMetal)服务器环境
- 通过适配器模式接入不同环境
- 为未来多集群部署预留扩展性

### 5. 健康检查

灵活的健康检查机制,确保应用可用性:

- **HTTP 检查**: 通过 HTTP 接口检查应用状态
- **TCP 检查**: 检查 TCP 端口连通性
- **自定义脚本**: 支持执行自定义健康检查命令

### 6. 监控集成

与 Prometheus 监控系统集成,提供实时应用性能数据:

- CPU 使用率监控
- 内存使用率监控
- 自定义业务指标监控
- 基于监控数据的自动决策

## 使用场景

### 场景 1: 新版本灰度发布

在正式发布新版本前,先将新版本部署到 10% 的实例上,观察运行状况:

1. 配置渐进式发布策略: 10% → 50% → 100%
2. 系统自动执行分阶段发布
3. 每个阶段自动进行健康检查
4. 发现问题自动回滚,确保服务稳定

### 场景 2: 快速回滚故障版本

新版本上线后发现性能问题,需要快速回滚:

1. 系统自动检测 CPU 使用率异常
2. 触发自动回滚流程
3. 回滚到上一个稳定版本
4. 通过企业微信通知运维人员
5. 问题版本标记为"不稳定"

### 场景 3: 多环境统一管理

在不同环境(K8s、裸金属)部署相同应用:

1. 使用统一的发布配置，一套配置适用不同的服务部署环境
2. 系统自动选择对应环境的适配器
3. 在不同环境执行相同的发布流程
4. 统一的监控和管理界面

## 技术要求

### 基础设施

- PostgreSQL 18.0+ 数据库
- Prometheus 监控系统
- 企业微信 Webhook(用于通知)

## 限制说明

### MVP 版本限制

- 仅支持单集群部署(多集群支持将在后续版本提供)
- 发布状态机细节待进一步完善

### 安全限制

- 自定义健康检查脚本需经过安全审查
- 脚本执行有严格的超时和资源限制
