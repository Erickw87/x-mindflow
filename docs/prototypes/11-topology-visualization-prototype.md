# 拓扑可视化与交互界面 - 原型文档

**关联 Issue**: #11  
**文档类型**: 原型设计  
**创建日期**: 2025-10-24

## 📝 原型概述

本原型实现了 x-mindflow 智能发布系统的**拓扑可视化与交互界面**，基于 Issue #11 的需求设计，提供直观的图形化界面来理解和控制发布流程。

## 🎯 实现的核心功能

### 1. 横向树形布局
- ✅ 采用 AntV G6 的 Dagre 布局算法，实现从左到右的横向树状结构
- ✅ 支持分支结构展示（不兼容版本发布时的拓扑分叉）
- ✅ 自动布局，避免节点重叠
- ✅ 支持缩放（zoom-canvas）和平移（drag-canvas）操作

### 2. 节点展示

#### 服务节点
- 显示内容：
  - 服务名称
  - 总流量占比（如 "70% 流量"）
  - 实例数统计（如 "14 实例"）
- 样式：
  - 白色背景，浅灰边框
  - 圆角矩形
  - 阴影效果

#### LB 节点
- 显示内容：
  - "LB" 标识
  - 规则数量（如 "2 规则"）
- 样式：
  - 浅灰背景
  - 虚线边框
  - 较小尺寸（120x60）

### 3. 连接线
- ✅ 直接在连接线上显示流量占比数值（如 "70% 流量"）
- ✅ 带箭头指示流量方向
- ✅ 智能路由，避免边重叠

### 4. 交互能力

#### 展示模式（View Mode）
- 只读模式，不可修改拓扑结构
- 支持查看节点详情
- 支持缩放和平移操作

#### 编辑模式（Edit Mode）
- 可以进行拓扑修改（UI 已实现，具体编辑功能待后续开发）
- 提供保存配置按钮
- 提供重置功能

### 5. 流量百分比计算
- ✅ 实现了流量百分比的自动计算逻辑
- ✅ 显示每个节点的总流量占比
- 公式：节点总流量 = 上游百分比 × 中间节点百分比

## 🏗️ 技术架构

### 技术栈
- **框架**: Vue 3 (Composition API + `<script setup>`)
- **语言**: TypeScript
- **图可视化**: AntV G6 v5.0.50
- **状态管理**: Pinia
- **样式**: Tailwind CSS v4
- **构建工具**: Vite

### 核心组件说明

#### 1. TopologyView.vue
- **职责**: 主页面容器，提供模式切换、工具栏、侧边栏
- **功能**:
  - 模式切换（展示/编辑）
  - 重置按钮
  - 保存配置按钮
  - 图例说明
  - 功能说明

#### 2. TopologyGraph.vue
- **职责**: 拓扑图渲染核心组件
- **功能**:
  - 使用 AntV G6 渲染拓扑图
  - 响应式调整画布大小
  - 监听数据变化自动重新渲染
  - 自定义节点样式

#### 3. topologyStore.ts
- **职责**: 拓扑数据状态管理
- **功能**:
  - 存储拓扑数据（nodes + edges）
  - 管理当前模式（view/edit）
  - 提供增删改查节点和边的方法
  - 重置为 Mock 数据

#### 4. topology.ts
- **职责**: 类型定义
- **包含类型**:
  - `ServiceNode`: 服务节点
  - `LBNode`: LB 节点
  - `TopologyEdge`: 连接边
  - `TopologyData`: 拓扑图数据
  - `TopologyMode`: 模式枚举
  - `LBConfig`: LB 配置

## 📊 Mock 数据场景

原型使用的 Mock 数据模拟了以下场景：

```
入口网关 (v2.0, 100% 流量)
    ↓
   LB1 (规则1: 70%, 规则2: 30%)
    ├─→ 服务 A v1.0 (70% 流量, 14 实例)
    │       ↓
    │      LB2 (规则1)
    │       ↓
    │   服务 B v2.0 (70% 流量, 10 实例)
    │       ↓
    │   服务 C v1.0 (70% 流量)
    │
    └─→ 服务 A v1.1 (30% 流量, 6 实例, 目标版本)
            ↓
           LB2 (规则1)
            ↓
        服务 B v2.1 (30% 流量, 5 实例, 目标版本)
            ↓
        服务 C v1.0 (30% 流量)
```

**场景说明**:
- 服务 A 正在从 v1.0 灰度发布到 v1.1（30% 流量）
- 服务 B 同时在进行 v2.0 → v2.1 的发布
- 服务 C v1.0 是共享节点，被两个分支共同使用
- 展示了分支拓扑结构的场景

## 🚀 运行原型

### 前置要求
- Node.js 20+
- npm

### 启动步骤

```bash
# 进入前端目录
cd frontend

# 安装依赖（如果尚未安装）
npm install

# 启动开发服务器
npm run dev

# 浏览器访问
# Vite 会提示访问地址，通常是 http://localhost:5173
```

### 构建生产版本

```bash
cd frontend
npm run build
```

构建产物位于 `frontend/dist/` 目录。
